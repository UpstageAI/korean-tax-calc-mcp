# SPEC_export_workbook_b — 엑셀 내보내기 검수 반영 · 작성 Claude 2026-10-24

브랜치 `feat/export-workbook`(이어서). 정답 테스트 `tests/test_export_workbook_b.py` 7개 + 기존 전부 통과(`tests/test_export_workbook.py` 포함). 커밋 1개(제목은 실행 지시대로). push 금지, 테스트 수정 금지.

## 고칠 것
1. **계산 시트가 다른 call의 `계산` 값을 씀.** `calc_dict = data.get("계산")`의 `data`가 실행 루프의 마지막 값이라, 모든 `계산 N` 시트에 마지막 call의 `계산`이 들어간다. 각 시트는 **자기 call의 결과 dict**(`cd["data"]`)에서 `계산`을 읽는다.
2. **확인 셀이 숫자를 문자열과 비교.** `=IF(B11="13000000",…)`은 엑셀에서 항상 "확인 필요". 비교값은 따옴표 없는 숫자로: `=IF(B11=13000000,"일치","확인 필요")`. 세무조정 표가 없으면 확인 셀을 만들지 않는다(지금은 `합계_수식행`이 정의되지 않은 채 참조될 수 있음).
3. **가산·차감을 구분하지 않고 SUM.** 세무조정 항목에는 익금산입(가산)과 손금산입(차감)이 섞인다. 표에 `조정` 열(값 `가산`/`차감`)을 추가한다(열 순서 `구분 | 조정 | 금액 | 소득처분`).
   - 분류: 항목에 `조정` 키가 있으면 `익금산입`·`손금불산입` → 가산, `손금산입`·`익금불산입` → 차감. 없으면 `소득처분`이 `△`로 시작하면 차감, 그 밖은 가산.
   - 합계 행은 `가산 합계 =SUMIF(조정열,"가산",금액열)`, `차감 합계 =SUMIF(조정열,"차감",금액열)`, `순액 =가산합계셀-차감합계셀`. 소득처분별 합계(SUMIF)는 그대로 둔다. 전체 `=SUM(금액열)` 행은 `금액 합계(방향 무관)`라는 이름으로 남겨도 된다.
   - 확인 셀: 결과에 `익금산입_손금불산입`이 있으면 가산 합계 셀과, `손금산입_익금불산입`이 있으면 차감 합계 셀과 각각 비교. 그 밖에는 기존처럼 `손금불산입_합계`·`한도초과` 순으로 찾아 가산 합계 셀과 비교. 라벨 `확인 (키 이름)`.
4. **income_adjustment_total 세무조정 항목에 `조정` 키 추가**: 익금산입 쪽은 `"조정": "익금산입"`, 손금산입 쪽은 `"조정": "손금산입"`. 기존 키(구분·금액·소득처분)와 다른 결과 키는 그대로.
5. **없는 도구 이름이면 전체 중단하던 것** → 그 call만 오류로 기록하고 계속(명세 원문: "결과에 error가 있어도 중단하지 않고 그 call을 오류로 기록"). `오류_call`에 label, 요약 시트에 오류 문장. tool 이름이 비었거나 `export_workbook` 자신이면 지금처럼 전체 error.
6. 입력·가정 시트의 args는 call 순서(인덱스)로 찾는다(label이 겹쳐도 맞는 args). 세무조정 `금액`이 숫자가 아니면 `int()`로 죽지 말고 셀에 그대로 쓰고 합계 수식에서는 빠지게(문자 셀은 SUM에서 무시됨).

7. **(2차) 수식이 엉뚱한 열을 가리킴.** 세무조정 표는 `A 구분 | B 조정 | C 금액 | D 소득처분`인데 SUMIF 합계 범위·순액·확인 셀이 D열(소득처분)을 가리킨다. 금액 범위는 C열, 소득처분 조건 범위는 D열, 순액은 `=C가산행-C차감행`, 확인 셀은 C열 합계 셀을 참조. 정답 테스트 `test_formulas_evaluate_to_tool_values`가 수식을 직접 계산해 가산 8,000,000·차감 2,000,000·순액 6,000,000과 모든 확인 셀 "일치"를 본다.
- 정정(Claude): 테스트의 차가감 기대값 108,000,000은 Claude 오기 → 106,000,000(100 + 8 − 2). 기존 `test_export_workbook.py`의 없는 도구 거절 기대도 이 명세 5번에 맞춰 Claude가 고침(오류 call 기록).

8. **(3차) 근거가 목록인 도구에서 실행 오류.** `common_input_tax`·`bundled_supply_split`은 근거를 `[[법령, 조, 항, 요지], …]`로, `earned_income_gross_pay`는 항목별로 한 겹 더 감싼 목록으로 돌려준다. 이것을 셀에 그대로 넣어 `ValueError: Cannot convert [...] to Excel`로 도구 전체가 죽는다.
   - 셀에 쓰는 모든 값은 스칼라(문자·숫자·None)만. 목록·dict는 문자열로 바꿔 쓴다.
   - 근거 목록은 사람이 읽는 문장으로: 안쪽 목록 `[법령, 조, 항, 요지]`는 빈 값을 빼고 `법령 조항 — 요지`(요지가 없으면 `법령 조항`), 겹친 목록은 펼쳐서, 줄바꿈으로 잇는다. 예: `부가가치세법 제40조 — 실지귀속 우선, …`, `부가가치세법 시행령 제81조① — 면세 관련 = …`. 셀은 줄바꿈 표시(wrap).
   - 판단 항목의 근거·이유·결론도 같은 규칙. 그 밖의 목록·dict(예: depreciation_adjustment 계산의 상각범위액 내역 목록)는 `json.dumps(ensure_ascii=False)`. 셀에 값을 넣는 곳을 한 함수(`_cell_value`)로 모아 빠지는 곳이 없게.
   - 정답 테스트 `test_demo_case_exports_all_calls`: 가상 사례 8개 call(법인 4·부가 2·소득 2)이 오류 없이 나오고, 요약에 `부가가치세법 제40조` 문장, 차가감 시트에 320,630,000, 모든 확인 셀 "일치".

9. **(4차) 근거 문장 자리 밀림·중복 합계 행.** `_format_basis`가 빈 값을 먼저 걸러낸 뒤 위치로 읽어, 항이 빈 근거(`["부가가치세법", "제40조", "", "요지"]`)의 요지가 항 자리에 붙음 → `부가가치세법 제40조실지귀속 우선…`. 자리(0 법령·1 조·2 항·3 요지)로 먼저 읽고 빈 값만 생략: `부가가치세법 제40조 — 실지귀속 우선, 공통매입세액은 안분기준으로 안분`. 또 세무조정 표 아래 `금액 합계(방향 무관)`와 `합계`가 같은 수식으로 두 번 나옴 → `합계` 행 삭제(확인 셀은 `금액 합계(방향 무관)` 셀 참조). 정답 테스트 `test_basis_lines_keep_positions`.
