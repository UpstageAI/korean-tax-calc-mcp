# SPEC_export_workbook — 계산 근거 엑셀 내보내기 · 작성 Claude 2026-10-24

브랜치 `feat/export-workbook`(main에서). 정답 테스트 `tests/test_export_workbook.py` 3개 + 기존 전부 통과. 커밋 1개(제목은 실행 지시대로). push 금지, 테스트 수정 금지.

## 왜
계산 결과를 실무자가 검토할 수 있는 형식으로 남긴다. 보고서(쟁점·판단 요지·과세소득 집계)는 한글(korean-report-hwpx), 금액이 어떻게 나왔는지는 엑셀. 우리 도구는 이미 입력·항목별 판단·근거 조문·산식·세무조정을 돌려주므로 그것을 탭으로 펼친다.

## 도구 export_workbook
입력: `title`(문서 제목), `calls: [{label, tool, args}]`(1~30개), `output_dir`(기본: 현재 작업 폴더), `filename?`(기본: title, 확장자 .xlsx 자동)
동작:
- 각 call을 **도구가 직접 다시 실행**한다(같은 서버의 도구를 이름으로 호출, 모델이 결과를 옮겨 적지 않게). 결과에 error가 있어도 중단하지 않고 그 call을 오류로 기록.
- tool 이름이 없거나 `export_workbook` 자신이면 error(재귀 금지). calls가 비었거나 30개 초과면 error. output_dir가 없으면 error.
- 같은 파일이 있으면 덮어쓰지 않고 `이름 (2).xlsx`처럼 새 이름. 파일명의 `/ \ : * ? " < > |`는 `_`로.
- 의존성 `openpyxl` 추가(pyproject dependencies).
시트(이 순서):
1. `요약`: 제목, 작성일, call마다 한 행 — label, 도구, 핵심 결과(결과 dict의 숫자 값들 `키=값`을 열로 펼치거나 키/값 두 열 반복), 근거 문자열, 오류 시 오류 문장. 맨 아래 고지 행: `"이 파일은 계산 도구의 결과를 정리한 참고 자료이며 세무 자문이 아닙니다. 판단과 신고는 세무 전문가와 확인하세요."`
2. `계산 1`, `계산 2`… (call마다, 오류 call은 생략): ① `결과`·`계산` dict의 숫자·문자 값을 `항목 | 금액` 표로 ② `세무조정` 목록이 있으면 `구분 | 금액 | 소득처분` 표와 그 아래 합계 행을 **엑셀 수식** `=SUM(B?:B?)`로, 소득처분별 합계는 `=SUMIF(...)` ③ 도구 결과의 합계 값과 수식 합계를 비교하는 확인 셀 `=IF(합계셀=값,"일치","확인 필요")` ④ `산식` 문자열.
3. `입력·가정`: call마다 args를 펼친 표 — `call | 경로(예 revenue.매출액, ledger[0].금액) | 값`. 숫자는 숫자 셀로.
4. `판단·근거`: call마다 판단 목록 — `call | 항목 | 결론 | 금액 | 근거 | 이유`(없는 키는 빈칸).
- 금액 셀 서식 `#,##0`, 머리행 굵게·고정(freeze), 열 너비 적당히.
결과: `결과.파일`(절대경로), `결과.시트`(시트 이름 목록), `결과.call_수`, `결과.오류_call`(label 목록), 근거 `"계산 도구 결과 정리(세무 자문 아님)"`.
