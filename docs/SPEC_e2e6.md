# SPEC e2e6 — 계산기 사용 정돈: 원장형 입력·세무조정 출력·계산기 연결 (2026-10-14)

배경(26회차 호출 기록 분석): 끝에서 끝까지 계산기까지 간 12문항 중 9문항 오답. 원인은 계산 오류가 아니라 ① 결과가 세무조정 단위가 아님(2024-65) ② 입력 필드명이 실무 어휘와 안 맞아 사실을 빠뜨림(2025-76 현금영수증, 2024-76 실지귀속 배송료) ③ 계산기끼리 연결이 없어 중간값을 모델이 손으로 계산(2025-71 일괄공급→재계산) ④ 항목 판단 어휘 부족(2026-62 교제목적 광고비·직원단체 복리시설비·현물·특수관계 매출할인). 이 명세는 그 네 가지만 고친다. 규칙·기준값은 전부 어휘(`facts_vocab.json`, Claude 검증본·수정 금지)에서 읽을 것(코드 상수 금지).

대상 korean-tax-calc-mcp 0.8.0. 기존 입력 방식은 전부 그대로 유지(하위 호환). 새 입력은 **대안**이며 둘 다 주면 `error`.

## A. 법인세 세무조정 계산기 출력 통일 — `bad_debt_adjustment`, `entertainment_adjustment`
`결과` dict의 **첫 키**를 아래 순서로 둔다(기존 키는 그 뒤에 유지, 최상위 `세무조정`도 유지).
```
"결과": {
  "세무조정": [{"구분", "금액", "소득처분"}...],      # 조정명세서에 적는 모양 그대로
  "소득처분별_합계": {"대표자상여": n, "기타사외유출": n, "유보": n, "△유보": n},   # 0인 처분은 생략
  "손금불산입_합계": n,                                 # △유보(손금산입) 제외한 합
  ...기존 키
}
```

## B. 원장형 입력 — 항목명·금액·속성 목록으로 받고 항목 판단은 도구가
### B1. `entertainment_adjustment` 에 `ledger`, `revenue` 추가
- `ledger: list | None` — `expenses` 대안. 항목: `{항목: str(계정과목·설명, 자유), 금액: 원, 증빙: '없음'|'영수증 등'|'적격'(기본 '적격'), 성격?: '교제목적'|'직원단체_법인'|'직원단체_비법인'|'임직원부담'|'현물'|'경조금'|'문화', 시가?: 원, 장부가액?: 원, 건당기준초과?: bool(기본 true)}`
- 성격별 판단(어휘 `기업업무추진비_포함항목`.판단.성격별에서 읽음):
  - 없음·교제목적 → 포함(법 제25조①: 접대·교제·사례 등 명목 불문)
  - 직원단체_법인 → 포함(영 제40조②) / 직원단체_비법인 → 제외, 결론 "복리후생비(경리의 일부)"(영 제40조②)
  - 임직원부담 → 제외(영 제40조①)
  - 현물 → 포함, 금액 = max(시가, 장부가액)(영 제42조⑥ → 영 제36조①3호 준용). `금액`이 없으면 이 값, 시가·장부가액 둘 다 없으면 `error`
  - 경조금·문화 → 기존 congratulatory·culture와 동일
- 포함된 항목은 기존 `expenses` 규칙(증빙별 직부인·시부인)을 그대로 탄다. 제외 항목은 `판단`에 "제외·근거"로만 남기고 금액 계산에 넣지 않는다
- `revenue: dict | None` — `revenue_general`/`revenue_related` 대안. `{매출액: 원, 특수관계매출: 원(기본 0), 매출할인등: {일반: 원, 특수관계: 원}(기본 0)}` → revenue_related = 특수관계매출 − 매출할인등.특수관계, revenue_general = 매출액 − 특수관계매출 − 매출할인등.일반 (영 제42조①: 기업회계기준 매출액 = 매출에누리·환입·할인 차감 후). 음수가 되면 `error`
- `ledger`와 `expenses` 둘 다 / `revenue`와 `revenue_general·revenue_related` 둘 다 → `{"error": ...}`
- `판단`에 항목마다 {항목, 성격, 결론(포함|제외), 금액, 근거}

### B2. `simplified_vat_return` 에 `ledger` 추가
- `ledger: dict | None` — `supplies`·`purchases` 대안. `{"공급": [{항목, 금액}], "매입": [{항목, 금액}]}`. 금액은 공급대가(부가세 포함)
- 항목명 → 역할 매핑은 어휘 `간이과세자_원장항목`.판단으로: 공급·매입 각각 `판단.공급`/`판단.매입`에 적힌 **순서대로** 역할의 `키워드`가 항목명에 포함되는지 검사해 처음 맞는 역할을 쓴다(예: '세금계산서 미수취분'은 '미수취'가 먼저 맞아 미수취가산세, '세금계산서 수취분'은 세금계산서등수취, '계산서 수취분'은 계산서수취). 역할의 `처리`에 적힌 기존 필드로 변환:
  - 공급: 신용카드매출전표 발급분·현금영수증 발급분·직불카드/기명식선불카드 발급분 → 발급세액공제 대상(제46조①2호) / 영수증 발급분·기타 과세 공급 → 대상 아님 / 자기적립마일리지 결제분 → 과세표준 제외(영 제61조②9호)
  - 매입: 세금계산서 수취분·신용카드매출전표등 수취분 → 세금계산서등수취세액공제(제63조③1호) / 계산서 수취분 → 공제 없음 / 세금계산서 미수취(발급의무자로부터) → 미수취가산세(제68조의2②1호) / 면세농산물 → 공제 없음
  - total = 공급 금액 전부 합(마일리지 포함), card_receipt_issued = 공제 대상 합, self_mileage = 마일리지 합. 매입도 같은 식으로 기존 필드로 변환한 뒤 기존 계산 그대로
- 어휘에 없는 항목명 → `{"error": "입력 확인 필요 — 계산하지 않음", "문제": [...], "허용값": {항목명: 역할}}` (계산하지 않음)
- `ledger`와 `supplies`/`purchases` 둘 다 → `error`

### B3. `common_input_tax` 에 `ledger`, `prior_common_input_tax` 추가
- `ledger: list | None` — `input_tax` 대안. 당기(이번 신고 기간) 매입 항목 `{항목, 매입세액?: 원 | 매입가액?: 원(→ ×10%), 사용처: '과세'|'면세'|'공통'|'실지귀속'|'불공제', 과세비율?: 0~1, 횟수?: {과세, 면세}, 면적?: {과세, 면적}}`
  - 과세 → taxable_only / 면세 → exempt_only / 불공제 → taxable_only_nondeductible(제39조) / 공통 → common.확정(예정신고면 common.예정) / 실지귀속 → attributed(taxable_ratio = 과세비율, 없으면 횟수 또는 면적의 과세 ÷ (과세+면세))(영 제81조①: 실지귀속을 구분할 수 없는 것만 안분)
  - 매입세액·매입가액 둘 다 없거나, 실지귀속인데 비율·횟수·면적이 없으면 `error`
- `prior_common_input_tax: int | None` — 확정신고에서 ledger를 쓸 때 예정신고 기간의 공통매입세액(common.예정). 기존 `prior_nondeductible`는 그대로
- `결과`에 `실지귀속_공제`는 기존 `계산` 키 유지

### B4. `input_tax_recalculation` 에 `bundle` 추가 — 계산기 연결
- `bundle: dict | None` — `input_tax` 대안. `{total_price, vat_included, appraisal?, standard_value?, book_value?}` (bundled_supply_split 입력과 동일). 주어지면 내부에서 `bundled_supply_split` 과 같은 규칙으로 건물 공급가액을 안분해 부가가치세를 `input_tax`로 쓴다
- `결과`에 `건물_매입세액`, `판단`에 안분 기준(감정평가가액 등) 한 줄 추가. `bundle`과 `input_tax` 둘 다 → `error`

## C. 어휘 추가 (Claude 검증본, Solar 수정 금지) — `기업업무추진비_포함항목`, `간이과세자_원장항목`, `공통매입세액_귀속`
